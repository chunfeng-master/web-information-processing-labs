## 一、抽取电影子图

从 Freebase 电影数据中抽取了 1,600 部电影。程序分块读取压缩数据，保留头尾均为 Freebase 实体、关系名以 `film.film.` 开头的记录。抽样以电影为单位，用固定种子 2026 计算各电影 ID 的哈希值，取值最小的 1,600 部，再保留这些电影符合条件的全部记录。同一部电影的导演、类型和语言等信息由此保存在同一个子图中。

去重后得到 **8,639 条三元组、4,172 个实体、35 种关系**。1,600 是抽中的电影数，4,172 还包括这些边另一端的导演、语言、类型等实体。实体和关系各自从 0 开始连续编号，原 ID 和新编号的对应关系保存在 `data/metadata/`。

## 二、划分数据集

子图里有 2,289 个实体只出现一次。如果把它唯一的一条边分到测试集，训练时这个实体就一次也见不到。因此我先打乱三元组，每次留出一条边前，检查它的两个端点和关系在剩余训练数据里是否还有记录。留够 1,726 条后再打乱，平分给验证集和测试集。

| 文件 | 三元组数 | 用途 |
| --- | ---: | --- |
| train.txt | 6,913 | 训练模型，采负样本 |
| valid.txt | 863 | 选择训练轮数和参数 |
| test.txt | 863 | 评估尾实体预测结果 |

三份文件都放在 `data/freebase/`，每行按 `头实体 关系 尾实体` 写三个整数。检查后，三份数据没有重复交叉，训练集包含全部 4,172 个实体和 35 种关系。读入后，框架给每条训练边 `(h,r,t)` 加一条反向边 `(t,r+35,h)`。训练时一共有 13,826 条边；验证和测试用原方向。

## 三、TransE 训练与负采样

实体和关系分别用 32 维向量表示。取出头实体、关系和尾实体向量，各自做 L2 归一化，再算距离 `d = ‖h + r − t‖₂`。距离越小，尾实体排得越靠前。

生成负样本时，取一条训练三元组，保留头实体和关系，随机换掉尾实体。比如一部电影已知有两种语言，替换尾实体时，这两种都要排除。为此，程序按 `(h,r)` 存下训练图里所有已知的尾实体。训练损失用 `softplus(d正 − d负)` 加 L2 正则项；同一个查询下，正例距离越小、负例距离越大，排序损失就越小。

评估时，对每个查询的全部 4,172 个候选打分。如果同一部电影在同一关系下还有其他已知答案，就过滤这些答案，保留本次要预测的那个。MR 是正确答案的平均名次，越小越好；MRR 是名次倒数的平均值；Hits@5 和 Hits@10 分别统计正确答案排进前五和前十的比例。

## 四、调整训练方法

先只用 TransE 距离排序。我固定训练种子 2025，使用 Adam，学习率 0.001，L2 系数 0.0001。每组最多训练 80 轮，每 10 轮在验证集上评估一次。下表取各组验证 MRR 最高的那一轮。

| 正例采样方式 | 从同一关系抽负例的概率 | 批大小 | 轮次 | 验证 MRR | 验证 MR | 验证 Hits@10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 先抽头实体，再抽它的一条边 | 0 | 2,048 | 80 | 0.2761 | 160.33 | 48.09% |
| 打乱全部训练边，每条用一次 | 0 | 2,048 | 60 | 0.3643 | 79.16 | 59.10% |
| 同上 | 0.50 | 2,048 | 80 | **0.4132** | 228.43 | **62.57%** |
| 同上 | 0.50 | 512 | 70 | 0.4048 | 232.78 | 60.60% |
| 同上 | 0.85 | 512 | 60 | 0.3578 | 332.50 | 52.95% |

第一处改动是让每条训练边在一轮里都用一次。原来先抽头实体，一部有很多出边的电影即使被抽到，也只用到其中一条。改成逐边训练后，在负采样方式相同的情况下，MRR 从 0.2761 提高到 0.3643，平均名次也从 160.33 提前到 79.16。

第二处改动是换一部分负例。预测语言时，从全部实体随机抽，很容易抽到导演或电影类型。我让一半的抽样尝试从训练中出现过的语言里选，遇到已知正确答案就退回全局抽样。这次前十命中率升到 62.57%，但平均名次退到了 228.43。这个设置更容易把一部分答案推到前面，排在后面的答案仍然拖累平均名次。

随后把批大小从 2,048 减到 512，MRR 降了 0.0084。再把关系内抽样概率加到 0.85，前十命中率又降了 7.65 个百分点。后面的实验采用第三组，保留一半全局抽样，用第 80 轮的权重。

## 五、改进尾实体排序

第 80 轮模型在测试集上的 MRR 为 0.4229。按关系拆开看，152 条语言查询的 MRR 为 0.6377，372 条类型查询为 0.2810，43 条电影节查询只有 0.0411。训练集中，语言关系有 69 个不同尾实体，电影节关系有 304 个。只靠同一种距离给所有候选排序，在这几类问题上的效果差别很大。

我保留同一份 TransE 权重，尝试把电影已有的属性也用于排序。下表每一行都保留上一行的方法，权重按验证集 MRR 选择。

| 做法 | 具体改动 | 验证 MRR |
| --- | --- | ---: |
| 只用 TransE | 计算 ‖h + r − t‖₂，按距离从小到大排序 | 0.4132 |
| 加入出现次数和相似电影 | 统计候选在该关系下出现的次数，再按电影已知属性的相似度，让相似电影给候选投票 | 0.5379 |
| 加入电影的其他属性 | 用逻辑回归，根据其他关系下的已知属性预测当前关系的常见答案 | 0.5379 |
| 加入经常一起出现的属性 | 用 EASE 从“电影 × 属性”矩阵估计属性之间的联系，系数矩阵的对角线置零 | 0.5579 |
| 遮住一个属性再预测 | 训练时拿掉目标属性，并将该关系的已知属性数减一，用逻辑回归和极端随机树预测被拿掉的属性 | **0.5591** |

出现次数和相似电影带来的提高最大，验证 MRR 一次提高了约 0.125。单独再加逻辑回归的变化很小，保留四位小数时看不出差别。属性共现多提高了约 0.020；这一步试了正则强度 30 和 3，取 3 略好。最后一步的提高只有约 0.0012。我还试过用伯努利混合模型估计一部电影可能具有哪些属性，验证集选出的权重是 0，因此去掉了这项计算。

最终分数等于负的 TransE 距离，加上表中后四项的加权分数。验证集选出的四个权重依次为 0.15、0.05、3、0.05。出现次数、相似电影和分类器都来自训练集，测试时仍在全部实体中排名。

## 六、测试结果

| 排序方法 | MRR | Hits@5 | Hits@10 | 平均名次 |
| --- | ---: | ---: | ---: | ---: |
| TransE 距离 | 0.4229 | 52.84% | 60.95% | 242.89 |
| TransE 距离与电影属性联合排序 | **0.5635** | **71.03%** | **78.91%** | **48.17** |

在同样的 863 条查询里，正确答案进入前十的次数从 526 次增加到 681 次，增加了 155 条。这个测试集中，类型、国家或地区、语言三类占了 726 条。主演关系虽然在子图里有 393 条，因为划分时要保留训练集的实体覆盖，测试集里一条也没有。因此，这组成绩主要反映常见电影属性的补全情况。

## 运行方法

实验使用 Python 3.10.19、PyTorch 2.8.0（CPU）、NumPy 2.0.2 和 pandas 2.3.3。第五节的排序还用到了 SciPy 1.13.1、scikit-learn 1.6.1 和 threadpoolctl。

在 `lab2` 目录下运行以下 PowerShell 命令。需要从压缩包重新抽取子图时，运行 `python -B framework/loader_kg.py`。

```powershell
$runDir = Join-Path $env:TEMP ("lab2-" + [guid]::NewGuid())
python -B framework/main_kg.py --save_dir $runDir
$checkpoint = (Get-ChildItem $runDir -Filter '*.pth').FullName
python -B framework/main_kg.py --mode test --pretrain_model_path $checkpoint
python -B framework/main_kg.py --mode fusion --pretrain_model_path $checkpoint
```
