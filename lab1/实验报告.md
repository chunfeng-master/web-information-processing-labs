## 一 实验环境与数据说明

本实验使用课程提供的 Qilin-IR-50K 教学子集，包含 50,000 篇中文笔记。必做部分使用 `documents.jsonl`、`queries.jsonl` 和 `search_logs.jsonl`；`optional/` 下的数据只用于选做推荐任务，本实验未使用。

实验环境如下：

- Python 3.12
- jieba 0.42.1
- NumPy 2.3.5
- sentence-transformers 6.1.0
- 预训练模型 `paraphrase-multilingual-MiniLM-L12-v2`
- SQLite 用于保存未压缩和压缩倒排索引

标题和正文采用合并处理：`text = title + " " + content`。标题只出现一次，标题中的词项位置排在正文之前。随机种子固定为 2026。

## 二 【必做】文档分词与规范化处理

### 2.1 数据读取与文本组织

程序逐行读取 `documents.jsonl`，提取 `doc_id`、`title` 和 `content`。空标题或正文统一视为空字符串。合并后的文本同时送入匹配分词方法和统计分词方法。

### 2.2 基于匹配的分词方法

匹配方法采用双向最大匹配 BM，包括正向最大匹配 FMM 和反向最大匹配 RMM。

正向最大匹配从左到右选择词典中能够匹配的最长词；反向最大匹配从右到左执行相同过程。两种结果按以下规则选择：

1. 优先选择词项数量更少的结果。
2. 词项数量相同时，选择单字词数量更少的结果。
3. 两项仍相同时，保留正向最大匹配结果。

词典使用 jieba 内置词典，最长匹配长度设为 8。程序对全部 50,000 篇文档执行双向最大匹配，结果保存在：

```text
outputs/matching_tokens_full.jsonl
```

每行包含：

```json
{
  "doc_id": 52,
  "keep": ["保留停用词的词项"],
  "remove": ["去除停用词的词项"]
}
```

### 2.3 基于统计的分词方法

统计方法使用 jieba 的 HMM 模式。该方法将中文分词视为序列标注问题，由统计模型辅助识别未登录词和组合词。

HMM 同样处理全部 50,000 篇文档，结果保存在：

```text
outputs/normalized_tokens_full.jsonl
```

HMM 去除停用词后的词项总数为 5,224,103，词汇表大小为 197,504。

### 2.4 两种分词方法的对比

为便于量化分析，程序对前 200 篇文档统计分词差异：

| 方法 | 前 200 篇产生的词项数 |
|---|---:|
| 双向最大匹配 BM | 34,410 |
| jieba HMM | 33,540 |

前 200 篇中，只有 7 篇文档的完整分词边界完全相同，说明两种方法在社交媒体文本上存在明显差异。

以文档 52 的片段为例：

```text
原文：C哥预测还准不准 之前刷小红书经常看到uu说中两三篇……

BM：C / 哥 / 预测 / 还 / 准 / 不准 / 之前 / 刷 / 小红 / 书经 / 常看到 / uu……

HMM：C / 哥 / 预测 / 还准 / 不准 / 之前 / 刷小红书 / 经常 / 看到 / uu……
```

BM 依赖词典并偏向最长匹配，在“刷小红书”等口语化表达上可能产生错误边界；HMM 能利用统计信息识别部分组合词，但也可能把不应连接的口语词连接起来。考虑到小红书文本中包含大量口语和新词，后续主索引采用 HMM 结果，同时保留 BM 全量结果用于对照。

### 2.5 规范化处理

规范化流程如下：

1. 使用 Unicode NFKC 统一全角、半角和兼容字符。
2. 将拉丁字母转为小写。
3. 合并连续空白字符。
4. 去除标点、表情和其他特殊字符。
5. 将纯数字统一为 `<num>`。
6. 分别保存保留停用词和去除停用词两套结果。

停用词表以常见中文虚词为主，包括“的、了、和、是、在、我、这个、那个”等。根据课件对停用词风险的说明，程序有意保留“非、不、未”等否定词，避免删除对语义有决定作用的词项。

两套结果均保存，而不是只在内存中临时处理，因此能够直接支持后续文档表征检索中的停用词对照实验。

## 三 【必做】倒排表的构建

### 3.1 倒排表结构

主索引基于 HMM 去除停用词后的结果构建。每个词项对应一个按 docID 递增排列的倒排表，每条倒排记录包含：

```text
(doc_id, term_frequency, positions)
```

其中：

- `doc_id` 表示文档编号。
- `term_frequency` 表示该词项在文档中的出现次数。
- `positions` 表示词项在标题和正文合并文本中的全部位置。

未压缩位置倒排索引保存在：

```text
outputs/inverted_index_full.sqlite
```

SQLite 中包含以下表：

| 表名 | 作用 |
|---|---|
| `docs` | 保存 docID、标题、正文和文档长度 |
| `postings` | 保存 term、docID、词频和位置 |
| `meta` | 保存文档数、词项总数和分词设置 |

`postings` 使用 `(term, doc_id)` 作为联合主键，使同一词项的倒排记录按文档编号有序。

### 3.2 倒排表构建流程

构建过程如下：

1. 逐篇读取文档并完成分词和规范化。
2. 在当前文档中建立 `term -> positions` 映射。
3. 由位置数量得到词频 TF。
4. 将 `(term, doc_id, tf, positions)` 写入索引。
5. 利用 `(term, doc_id)` 主键形成有序倒排表。

最终索引覆盖 50,000 篇文档，包含 197,504 个不同词项和 5,224,103 个规范化词项实例。

### 3.3 跳表指针设计

为加快两个有序倒排表的交集运算，程序实现单层跳表指针。若当前位置的跳转目标仍小于或等于另一个倒排表的当前 docID，则直接跳过中间记录；否则按普通方式移动一个位置。

课程介绍的启发式策略是对长度为 L 的倒排表设置约 `sqrt(L)` 的步长。实验额外比较步长 1、2、4、8、16、32 和 `sqrt(L)`：

| 步长 | 指针数 | 比较次数 | 跳跃次数 | 平均耗时 ms |
|---:|---:|---:|---:|---:|
| 1 | 0 | 4,370 | 0 | 0.5841 |
| 2 | 2,801 | 3,792 | 578 | 0.6347 |
| 4 | 1,400 | 4,094 | 92 | 0.7548 |
| 8 | 700 | 4,349 | 3 | 0.7901 |
| 16 | 349 | 4,370 | 0 | 0.7875 |
| 32 | 174 | 4,370 | 0 | 0.7368 |
| 48，约为 sqrt(L) | 115 | 4,370 | 0 | 0.7176 |

步长 2 将比较次数从 4,370 降至 3,792，但 Python 层的跳转判断增加了运行开销，所以平均时间没有同步下降。这说明跳表的实际收益不仅取决于比较次数，也取决于倒排表分布、实现语言和缓存状态。较短步长需要更多指针，体现了空间和检索效率之间的权衡。

## 四 【必做】倒排表的扩展与优化

### 4.1 在倒排表中加入词项位置信息

位置从合并文本的第 0 个词项开始记录。例如某词项在一篇文档中的位置为 `[3, 8, 15]`，表示它在该文档中出现三次，词频为 3。

短语检索先对所有查询词项的 docID 倒排表做 AND，再在候选文档中检查是否存在连续位置：

```text
p, p+1, p+2, ...
```

实验选择短语“旅游攻略”，查询词项为 `旅游` 和 `攻略`：

| 检索方法 | 结果数 |
|---|---:|
| 普通 AND 共现检索 | 1,233 |
| 带位置约束的短语检索 | 748 |

普通 AND 比短语检索多返回 485 篇文档。这些文档同时包含“旅游”和“攻略”，但两个词没有相邻且顺序一致。

被位置条件排除的示例是文档 2497《宝鸡这家的老虎斑鱼比在海边吃还鲜嫩》。正文末尾分别包含“宝鸡攻略”和“宝鸡旅游”，两个词都出现，但没有构成“旅游攻略”这一连续短语。该案例说明位置倒排表能够排除普通 AND 的伪匹配。

### 4.2 索引压缩方法一 按块存储

按块存储用于压缩词典。若块大小为 K，则每 K 个词项共用一个块指针，块内保存词项长度。相对于每个词项都保存指针，按块存储能够减少指针数量，但查找时需要在块内进行线性扫描。

### 4.3 索引压缩方法二 前端编码

词典按字典序排列后，相邻词项经常具有公共前缀。前端编码保存：

```text
公共前缀长度 + 当前词项剩余后缀
```

本实验将前端编码与按块存储结合，并比较不同块大小：

| 块大小 | 压缩词典字节数 | 相对未压缩比例 |
|---:|---:|---:|
| 2 | 1,650,701 | 0.517 |
| 4 | 1,571,924 | 0.493 |
| 8 | 1,532,622 | 0.480 |
| 16 | 1,512,583 | 0.474 |
| 32 | 1,502,915 | 0.471 |

未压缩词典估算为 3,191,120 字节。块大小 32 时压缩到 1,502,915 字节，节省约 52.9%。块越大，指针数量越少、空间占用越低，但块内线性查找成本增加。

### 4.4 倒排表的间距编码和可变字节码

除实验要求的两种词典压缩方法外，程序还实现了课件中的 docID 间距编码和可变字节码 VB。

对于有序 docID：

```text
33, 47, 154, 159
```

先转换为间距：

```text
33, 14, 107, 5
```

再使用 VB 对小整数分配较短编码。词频、位置数量和位置间距也采用 VB 编码。

| 索引组成 | 未压缩字节数 | 压缩字节数 | 压缩后比例 |
|---|---:|---:|---:|
| 词典，块大小 32 | 3,191,120 | 1,502,915 | 0.471 |
| 倒排记录 | 61,961,084 | 17,044,068 | 0.275 |

程序生成了可以直接查询的压缩索引：

```text
outputs/compressed_index_full.sqlite
```

该文件实际大小为 32,337,920 字节。它不仅用于估算压缩率，也参与后续压缩前后的检索效率实验。

## 五 【必做】多种形式的信息检索

### 5.A 布尔检索

#### 5.A.1 不少于三种复杂查询及处理顺序分析

实验设计以下三种带 AND、OR 和括号的复杂查询：

| 布尔表达式 | 两个中间结果大小 | 最终结果数 | 平均耗时 ms |
|---|---:|---:|---:|
| `(旅游 OR 攻略) AND (北京 OR 上海)` | `[4370, 1828]` | 403 | 0.6774 |
| `(减肥 OR 健身) AND (饮食 OR 运动)` | `[1586, 1625]` | 487 | 0.3249 |
| `(大学 OR 考研) AND (专业 OR 复试)` | `[1384, 1437]` | 243 | 0.2868 |

OR 先对组内倒排表求并集，AND 再对两个中间结果求交集。

另外对 `旅游 AND 攻略 AND 酒店` 比较三种执行顺序：

| 执行顺序 | 比较次数 | 结果数 | 耗时 ms |
|---|---:|---:|---:|
| 旅游 → 攻略 → 酒店 | 6,347 | 354 | 0.7636 |
| 酒店 → 攻略 → 旅游 | 6,347 | 354 | 0.7026 |
| 酒店 → 旅游 → 攻略 | 6,347 | 354 | 0.7074 |

所有顺序得到相同结果，说明处理顺序不会改变布尔语义。本组数据中三种顺序的比较次数相同，但耗时存在小幅差异。课程中“优先处理文档频率较低的倒排表”的策略主要通过缩小中间结果降低后续合并开销；实际耗时还会受到数据分布、缓存和 Python 调度影响。

#### 5.A.2 索引压缩前后的检索效率

对同一组 AND 查询分别使用未压缩位置索引和持久化压缩索引。每个查询重复 50 次，计时包括从 SQLite 读取倒排表、压缩索引解码和倒排表合并。

| 查询 | 结果数 | 未压缩平均 ms | 压缩平均 ms | 结果一致 |
|---|---:|---:|---:|---|
| 旅游 AND 攻略 | 1,233 | 8.9070 | 2.4252 | 是 |
| 减肥 AND 运动 | 192 | 3.6259 | 1.1035 | 是 |
| 大学 AND 复试 | 4 | 1.5072 | 0.5602 | 是 |
| 北京 AND 酒店 | 53 | 3.2398 | 1.0310 | 是 |

四组查询的结果集合完全一致，说明压缩和解码没有改变检索语义。在当前计算机和缓存条件下，压缩索引读取的数据量更小，足以抵消 VB 解码开销，因此四组查询都更快。该结果只代表本实验环境，不应直接视为其他硬件上的绝对性能。

#### 5.A.3 面向短语的检索

短语“旅游攻略”的实验已在 4.1 节详细说明。普通 AND 返回 1,233 篇，位置短语检索返回 748 篇，并成功排除两个词分散出现的文档。该结果直接体现了位置倒排表处理短语检索的作用。

#### 5.A.4 跳表步长对存储和检索效率的影响

步长实验已在 3.3 节给出。步长 2 设置 2,801 个指针，比较次数最低；较大步长减少指针存储，但在本查询上缺少有效跳跃。跳表优化效果与倒排表分布有关，不存在对所有查询均最优的固定步长。

### 5.B 向量空间模型

查询和文档采用相同的 HMM 分词和去停用词规则。词项权重为：

```text
TF_weight = 1 + log(TF)
IDF = log((N + 1) / (DF + 1)) + 1
```

最后计算查询向量和文档向量的余弦相似度并返回 Top10。

三个查询的前三名如下：

| 查询 | 排名 | docID | 余弦得分 | 标题 |
|---|---:|---:|---:|---|
| 毛巾变黄 | 1 | 263144 | 1.0000 | 女生皮肤超好的 10 点总结 |
| 毛巾变黄 | 2 | 1877054 | 0.9943 | 毛巾变黄一招洁净如新 |
| 毛巾变黄 | 3 | 70341 | 0.7772 | 03 女大穷游南京附机票省钱技巧 |
| 酒酿好处 | 1 | 621979 | 0.9514 | 酒酿蛋 |
| 酒酿好处 | 2 | 617141 | 0.7762 | 经期吃什么补气血 |
| 酒酿好处 | 3 | 1164023 | 0.7762 | 酒酿炖蛋能丰胸吗 |
| 收藏完整登机牌 | 1 | 147 | 0.9316 | 有收藏登机牌的习惯吗 |
| 收藏完整登机牌 | 2 | 413990 | 0.7441 | 位置前排预留 |
| 收藏完整登机牌 | 3 | 522802 | 0.7441 | 随心飞实战攻略 |

TF-IDF 对关键词直接重合敏感，速度快且容易解释，但无法充分识别同义表达和上下文。查询“毛巾变黄”的第一名受到文档词项分布影响，标题本身并不如第二名直接相关，说明仅依赖词面权重可能产生误排。

### 5.C 基于文档表征的检索

本实验使用预训练模型：

```text
sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
```

为控制 CPU 开销，先在完整 50,000 篇文档上使用 TF-IDF 召回 200 篇，再在相同候选集上进行语义重排。因此这是完整库召回加候选重排的两阶段检索，不是对全部 50,000 篇文档逐篇进行稠密向量穷举。

#### 5.C.1 不预先分词与预先分词

不预先分词方案将完整标题和段落一次输入模型，模型内部仍使用自带 tokenizer。

预先分词方案严格按照实验文档定义实现：

1. 使用 HMM 对文本预先分词。
2. 将每个词项分别输入同一个预训练模型。
3. 对每个词项得到一个 L2 归一化向量。
4. 对同一文档的全部词向量计算算术平均。
5. 再次归一化得到文档向量。
6. 查询采用相同的逐词编码与平均聚合方式。

这与“把分词结果用空格连接后整体输入模型”不同。当前实现确实逐词调用模型并聚合。

| 查询 | TF-IDF 与直接语义 Top10 重合率 | 直接语义与逐词聚合 Top10 重合率 |
|---|---:|---:|
| 毛巾变黄 | 0.10 | 0.50 |
| 酒酿好处 | 0.10 | 0.50 |
| 收藏完整登机牌 | 0.10 | 0.30 |

直接语义编码与逐词聚合的 Top10 重合率只有 0.30 至 0.50，说明预先分词明显改变了结果。原因是逐词平均会削弱词序和句子上下文，而完整段落编码能够保留更多组合语义。

查询“毛巾变黄”时：

- 直接编码前三名为“毛巾去黄失败”“毛巾没用多久就会有黄块”“毛巾变黄一招洁净如新”。
- 逐词编码前三名为“毛巾变黄一招洁净如新”“清洗毛巾”“毛巾发黄清洗小妙招”。

两种方法都能找到主题相关文档，但排序不同。逐词聚合更强调单个关键词，完整段落编码更强调文本整体语义。

数据中“毛巾变黄”对应 3 篇点击代理文档：

| 方法 | Recall@10 | MRR@10 |
|---|---:|---:|
| TF-IDF | 0.000 | 0.000 |
| 完整段落语义编码 | 1.000 | 1.000 |
| 逐词聚合并保留停用词 | 0.333 | 0.200 |
| 逐词聚合并去除停用词 | 0.667 | 0.333 |

点击只作为相关性的隐式代理，未点击不等于不相关。因此这些指标用于辅助案例分析，而不是严格的人工相关性评价。

#### 5.C.2 保留与去除停用词

在逐词编码方案中，分别使用保留停用词和去除停用词的词项集合，其余模型和候选集完全相同。

| 查询 | 保留与去除停用词 Top10 重合率 |
|---|---:|
| 毛巾变黄 | 0.70 |
| 酒酿好处 | 0.90 |
| 收藏完整登机牌 | 0.90 |

“毛巾变黄”的重合率最低，说明停用词处理对该查询影响更明显；另外两个查询只有一篇 Top10 文档发生变化。总体而言，去除停用词会改变排序，但头部主题结果相对稳定。

本实验没有简单删除所有高频虚词，而是保留否定词“非、不、未”。如果将否定词删除，“不变黄”和“变黄”可能被错误地视为相同语义。

### 5.D 向量空间模型与文档表征模型比较

三个查询中，TF-IDF 与直接语义检索的 Top10 重合率均为 0.10，说明两种模型的排序差异很大。

TF-IDF 的优势是速度快、实现简单、得分来源可解释，适合关键词精确匹配；缺点是依赖词面重合。同义表达或上下文相关但没有共享关键词的文档较难获得高分。

预训练语义模型能够识别更宽泛的语义关系，并在“毛巾变黄”的点击代理案例中取得更高 Recall@10 和 MRR@10；但语义模型也可能把主题宽泛相似、实际意图不同的内容排到前面，而且计算开销明显大于 TF-IDF。

因此，本实验采用 TF-IDF 完整库召回加语义模型候选重排。该结构同时利用了倒排检索的效率和预训练模型的语义理解能力。

## 六 实验结论

本实验完成了全部必做内容：

1. 对 50,000 篇文档执行双向最大匹配和 HMM 分词，并保留两种停用词设置。
2. 构建包含 docID、词频和位置的倒排索引。
3. 实现单层跳表并比较不同步长的存储与查询开销。
4. 利用位置倒排表完成短语检索并排除普通 AND 的伪匹配。
5. 实现按块存储、前端编码、gap 编码和可变字节码，比较压缩空间。
6. 使用真实压缩索引完成压缩前后的端到端查询效率比较。
7. 完成复杂布尔检索、TF-IDF 向量空间检索和预训练文档表征检索。
8. 完成不预分词、逐词编码聚合、保留停用词和去除停用词的对照分析。

实验结果表明，倒排索引能够显著减少查询时需要访问的数据；位置记录使精确短语检索成为可能；压缩方法明显降低索引空间，并在本实验环境中减少查询读取时间；TF-IDF 与语义模型具有互补性，适合组成两阶段检索系统。
